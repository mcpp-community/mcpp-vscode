# mcpp CLI 基础功能集成设计

## 背景

当前扩展已经能在 mcpp 工程中配置 clangd、监听编译数据库并检查 C++ 模块支持，
但日常的 mcpp 操作仍需在终端手动执行。本版本在不改变现有 clangd 集成边界的前提下，
增加工具链管理和常用项目命令。

本设计对应扩展 `0.2.0`。所有 README、CHANGELOG、代码注释、命令标题、提示和错误信息
均使用中文。

## 本版目标

本版提供以下能力：

- 从状态栏快捷菜单或命令面板执行 `mcpp build`、`mcpp run`、`mcpp test` 和
  `mcpp clean`；
- 查看已安装和可安装的工具链；
- 安装主机工具链；
- 通过 `mcpp toolchain default` 选择全局默认工具链；
- 在构建类任务结束后复用现有流程刷新 CDB 和 clangd；
- 对长任务提供实时终端输出、交互输入和取消能力。

## 非目标

本版不包含：

- 修改当前项目 `mcpp.toml` 中的 `[toolchain]`；
- 依赖搜索、添加、删除或更新；
- 选择构建 profile、工作区成员、target triple、feature 或 capability；
- 为 `mcpp run` 或 `mcpp test` 设置目标、过滤条件或运行参数；
- 清理全局 BMI 缓存；
- 自动下载工具链、自动切换全局默认工具链或自动执行构建；
- 新增侧边栏视图。

## 用户界面

### 状态栏入口

新增独立的 `$(tools) mcpp` 状态栏项，仅在当前活动编辑器属于 mcpp 工程时显示。
点击后打开 mcpp 快捷菜单。现有模块状态栏项继续只表示 clangd 模块能力，二者不合并。

快捷菜单按以下顺序组织：

1. 项目：构建、运行、测试、清理；
2. 工具链：查看工具链、安装工具链、选择全局默认工具链；
3. IDE：配置 clangd、刷新编译数据库、检查模块支持。

每项同时注册独立命令，允许用户直接从 VS Code 命令面板调用。

### 工具链操作

“查看工具链”执行 `mcpp toolchain list`，并用 Quick Pick 展示：

- 已安装的工具链和检测到的系统工具链；
- 当前有效工具链与全局默认项；
- mcpp 输出中声明的可安装工具链；
- 当前项目是否通过 `mcpp.toml` 覆盖全局默认值。

“选择全局默认工具链”只列出已安装项和检测到的系统工具链。用户确认后执行：

```text
mcpp toolchain default <family>@<version>
```

该命令只修改 mcpp 的全局配置 `~/.mcpp/config.toml`。若当前项目包含项目级
`[toolchain]`，插件明确说明该配置优先于全局默认值。

“安装工具链”优先列出 `mcpp toolchain list` 的可安装项，同时提供输入其他
`family@version` 的入口。确认后执行主机工具链安装：

```text
mcpp toolchain install <family>@<version>
```

本版不传递 `--target`。安装成功后重新读取工具链列表，并询问是否进入“选择全局默认
工具链”；由用户从包含准确安装版本的列表中选择，不根据部分版本输入猜测最终版本。

### 项目命令

项目命令使用当前活动编辑器所属的 mcpp 工程根目录作为工作目录：

```text
mcpp build
mcpp run
mcpp test
mcpp clean
```

构建、运行和测试直接使用 mcpp 默认行为。清理前明确确认将删除当前工程的
`target/`，且不使用 `--bmi-cache`。

## 执行模型

### 可执行文件解析

所有新增命令复用资源级设置 `mcpp.path`：

- 设置非空时使用该值；
- 设置为空时执行 `mcpp`，由 VS Code 进程环境的 `PATH` 查找；
- 扩展不假设 mcpp 来自 xlings，也不根据 clangd 或 CDB 编译器反推 mcpp 路径。

设置说明改为“供扩展执行全部 mcpp CLI 命令使用”。

### 长任务

构建、运行、测试、清理和工具链安装通过 VS Code Task 的 `ProcessExecution` 启动：

- 可执行文件和参数分别传递，不拼接 shell 字符串；
- 工作目录为目标 mcpp 工程根目录；
- 使用可见的专用终端实时输出；
- 用户可以向 `mcpp run` 启动的程序输入内容；
- 用户可以通过 VS Code 的终止任务功能取消任务；
- 插件等待任务结束事件，以区分成功、失败和取消。

### 短命令

工具链列表和设置全局默认值使用现有 `execFile` 风格的短时进程调用，便于读取退出码、
标准输出和标准错误。所有参数仍以数组形式传递。

### 构建后协调

`build`、`run` 和 `test` 都可能生成或更新编译数据库。任务结束后，无论退出码是否为
零，扩展都复用现有重协调入口：

1. 重新发现当前工程及 `compile_commands.json`；
2. 从 CDB 分析实际编译器；
3. 必要时更新并重启 clangd；
4. 重新执行模块支持检查。

普通源码错误不阻止插件消费已经成功生成的 CDB。

`clean` 成功或失败后都使当前模块检查结果失效，并重新检查现有 CDB，避免已经删除的
PCM 仍被显示为可用。

设置全局默认工具链后不自动构建，也不直接声称当前项目已经切换成功。插件显示结果并
提供“立即构建”操作；只有用户选择该操作后才生成新的 CDB 并刷新 clangd。

## 工具链列表解析

mcpp 当前没有为 `toolchain list` 提供 JSON 输出。本版只解析以下稳定语义：

- `Toolchains:` 区块中的 family、version、当前有效标记和已安装状态；
- `System:` 区块中检测到的系统工具链，例如 Windows 上的 MSVC；
- `Available toolchains` 区块中的 family 与 version；
- “effective toolchain from project mcpp.toml”提示及其中报告的全局默认值。

没有项目级覆盖时，星号项就是全局默认工具链；存在项目级覆盖时，星号项表示当前项目
有效工具链，全局默认值必须读取覆盖提示，二者不得混淆。

解析器不依赖列宽，并忽略不认识的辅助文本。解析结果必须保留原始输出。若无法得到任何
已安装项，插件不猜测工具链名称，而是把原始输出写入 `mcpp` 输出频道并报告兼容性错误。

## 安全边界

- 所有 mcpp 命令都要求工作区已受信任，包括工具链列表；
- 原因是 `mcpp.path` 可以来自工作区设置，不能在 Restricted Mode 中执行其指定程序；
- 工具链安装和全局默认值修改在执行前显示准确目标并要求确认；
- 清理操作在执行前显示准确工程路径并要求确认；
- 扩展不会因激活、打开工程、修改配置或切换编辑器而自动执行上述 CLI 操作；
- 外部进程始终使用参数数组，不通过 shell 解释用户输入。

## 多根工作区与并发

- 项目命令只作用于当前活动编辑器所属的 mcpp 工程；
- 后台工程不会因为前台命令而构建、清理或重新配置 clangd；
- 同一工程一次只允许运行一个由扩展启动的项目任务；
- 再次执行命令时聚焦已有任务，不并发写入同一构建目录；
- 工具链安装和全局默认值修改共享全局互斥状态；
- 取消任务不显示成功提示，也不把缺失退出码解释为成功。

扩展只能协调自己启动的任务，不阻止用户在外部终端直接运行 mcpp。

## 组件边界

实现按以下职责拆分：

- CLI 纯逻辑模块：命令参数、工具链数据类型、列表解析和结果分类；
- 任务纯逻辑模块：任务标识、并发状态和任务结束后的动作决策；
- VS Code 适配层：Quick Pick、确认框、Task、状态栏和命令注册；
- 现有 CDB/clangd 工作流：继续负责工程发现、配置、重启和模块检查。

纯逻辑模块不导入 `vscode`，使其可以继续使用当前 Node.js 测试运行器验证。

## 错误处理

- 进程启动失败时显示可执行文件和失败原因；
- 长任务的完整输出保留在 VS Code 任务终端，退出码和摘要写入 `mcpp` 输出频道；
- 短命令的标准输出、标准错误和退出码写入 `mcpp` 输出频道；
- 用户提示使用简短中文，并引导查看输出频道；
- 工具链输出解析失败时显示原始输出，不返回伪造的空列表；
- 任务取消、命令失败和 clangd 重协调失败分别报告；
- clangd 重协调失败不改写 mcpp 任务本身的退出结果。

## 测试与交付

在现有测试基础上增加：

- 工具链已安装项、系统项、有效项、全局默认项、可安装项和项目级覆盖提示解析；
- 工具链未知辅助文本及解析失败回退；
- build、run、test、clean、install、default 的参数数组；
- 同工程并发限制、全局工具链互斥和取消结果；
- 工具链切换后不自动构建；
- 构建类任务完成后请求 CDB/clangd 重协调；
- Restricted Mode 和多根工作区边界；
- `package.json` 命令、激活事件、版本与中文文案。

交付前执行：

```text
npm test
npm run compile
npm run package
```

随后生成 `mcpp-community.mcpp-vscode@0.2.0` VSIX，并覆盖安装到当前 VS Code。
真实完成哪些 Extension Host 图形操作会单独记录；未执行的 UI 端到端验证不得写成已通过。

## 后续计划

后续版本采用侧边栏视图，按工程展示：

- 当前工程及工作区成员；
- 实际生效的工具链、全局默认值和项目级覆盖；
- 构建 profile、target、feature、capability 和运行参数；
- 最近任务、运行状态、取消与重新执行；
- 依赖搜索、添加、删除和更新；
- CDB、clangd 和模块语义状态。

侧边栏只是交互层升级，仍复用本版建立的 CLI、任务和协调边界。
