# Libraries 与包详情页优化方案

日期：2026-10-18
状态：已实施并完成本地验证，等待 review（验证记录见 [本地验收](2026-10-19-libraries-local-verification.md)）
范围：索引来源、Libraries 浏览与搜索、包详情布局、版本选择、添加依赖及状态同步。

本文按本次要求放在 `.agnets/docs`；仓库已有文档目录实际为 `.agents/docs`，本次不迁移旧文档。

## 1. 结论与设计方向

Libraries 应围绕一条完整路径设计：**找到 C++ 库 → 判断能否使用 → 查看引入方式 → 为明确的项目添加明确的版本 → 得到准确反馈**。

先修数据来源和状态一致性，再优化显示层。延续侧边栏选包、编辑器区看详情的结构；保留单个详情面板、离线优先、简洁搜索工具栏、主操作与仓库/索引站按钮同行的已有决策。

建议本轮不加入多行筛选 chips、复杂卡片网格、评分/下载量、自动安装、自动修改版本、任意目标平台选择或在线 README 抓取。

### 2.1 已确认的问题

| 优先级 | 现状与证据 | 用户影响 |
| --- | --- | --- |
| P0 | 本机 mcpp 2026.10.16.3 的官方索引位于 `~/.mcpp/indices/mcpplibs`，含 252 个 Lua 描述符；插件只默认扫描 `registry/data` | 官方库漏读 |
| P0 | `rootAt()` 仅检查 `pkgs/`；本机旧扫描目录下 `xim-pkgindex` 含 337 个描述符 | Libraries 显示成 xim 包列表 |
| P0 | 快照 key 含索引 revision 和项目路径，不含 manifest/lock 内容；保存和添加后虽调用 refresh，仍可能命中旧快照 | 已添加徽标不更新 |
| P0 | 添加结果经共享 session 发给当前面板，没有绑定发起操作的包、项目或页面代次 | A 包添加期间切到 B，A 的结果可能把 B 标成已添加 |
| P1 | 网络搜索结果只在列表 `extra` 中；详情 `buildModel()` 只查本地 snapshot | 可点击的搜索结果打开后显示“不在本地索引” |
| P1 | 搜索有 debounce，但没有请求代次校验；旧请求可晚于新请求返回，关闭开关后也可能回填 | 搜索结果与当前关键词/开关不一致 |
| P1 | 详情创建后等待完整 `buildModel()` 才 paint，解析允许等待 20 秒 | 首次可能空白，切包期间可能仍显示上一包内容 |
| P1 | 所有平台的版本均为可点击按钮，选中状态只比较版本字符串 | 可误选其它平台独有版本；相同版本跨行同时高亮 |
| P1 | `installed` 合并 manifest 声明与 lock 解析状态；前端只保留版本字符串；dev 初始值未从现有声明恢复 | 已声明、已解析、依赖分组混淆；同版本切换分组无法准确表达 |
| P1 | 详情的项目通过当前编辑器动态获取，没有页面内明确目标；详情切换到活动编辑器本身也可能改变项目推断条件 | 多项目场景下难以判断写入哪个项目 |
| P2 | 详情为最长 900px 的纵向文档，版本、依赖在示例前；全部版本铺开 | 宽窗口利用不足，阅读用法需要滚动 |
| P2 | 复制、链接和添加共用一条结果栏，添加还触发通知；添加前端没有明确 pending 锁定 | 反馈互相覆盖、重复点击缺少解释 |

补充：当前只根据 extension host 的 `process.platform` 判定平台；这不能等同于工程交叉编译目标。界面应称“当前环境平台”，不得宣称完整验证了工具链、架构和 ABI 兼容性。

## 3. 索引来源与数据语义

### 3.1 默认源选择

1. 非空 `mcpp.library.indexPath` 优先。保留索引根目录、`pkgs/` 目录、索引集合目录三种输入；无效显式路径直接显示路径错误，不静默换源。
2. 默认发现 `<MCPP_HOME>/indices/mcpplibs`，兼容 `<MCPP_HOME>/registry/data/mcpplibs` 旧位置；同一 home 新位置有效时不再叠加旧位置。
3. home 选择遵循 CLI 的实际规则。建议实现时以本地 CLI 源码与 `self env --format json` 确认：显式环境 home 优先，默认 home 作为后备；需要 CLI 探测时每会话缓存，显式刷新/环境配置变更可重试。不把两个 home 中的同名官方源默认合并。
4. 默认不遍历加载全部 registry；官方源缺失时显示“未找到 mcpp-index”，即使 xim 已存在，也不能用 xim 填满列表。
5. 默认模式排除 xim；用户显式指定自定义源时允许浏览，但标题/来源须明确为自定义，不能标成官方。

“来源身份”与“官网链接”拆开建模：`official / custom / other-registry` 由发现路径和可核实元数据决定；有无 `site` 只决定是否展示官网按钮。集合配置中的同名包必须保留来源，选定优先级前不能静默覆盖。

底部简短显示 `mcpp-index · 252 个包 · 本地`，详细信息可展开查看实际路径、索引版本/更新时间（仅有真实元数据时显示）、最近更新结果。计数是本地快照数量，不保证等于远端当前总量。

### 3.2 缓存与刷新

- 索引内容缓存和项目依赖状态分离。刷新依赖状态只重读当前项目 manifest/lock，不重读数百个描述符。
- 索引缓存 key 包含源的规范路径、版本标记；显式本地重读可强制失效。源码 checkout 无更新 marker 时，应能检测描述符修改，不能只依赖根目录 mtime 和第一层目录数。
- 监听 manifest/lock 的保存及磁盘创建、变更、删除；去抖后同时更新列表和当前详情。项目切换、索引源/CLI 配置变化也应更新上下文。
- 区分两个操作：**重新读取本地索引**与**更新 mcpp 索引**。前者只读磁盘，后者执行 `mcpp index update`，可能联网。
- 更新失败保留上一次可用数据，标明未更新成功，并提供重试/查看输出；不把异常降级为空列表。
- 配置的是自定义 checkout 时，本地重读读取该路径；全局 `mcpp index update` 不承诺更新这个 checkout，操作说明必须指出其作用范围。

## 4. Libraries 列表交互与布局

### 4.1 工具栏与行结构

```text
Libraries                         [更新索引]
[搜索包名、命名空间、描述           ×]
☐ 搜索其它 registry                12 / 252
─────────────────────────────────────────
compat.argparse                     3.2
#include · 已声明
Command line argument parser…

openkal.types                       0.x
import
Type definitions…
─────────────────────────────────────────
mcpp-index · 本地                 [来源详情]
```

上图版本与描述仅为结构示意，产品显示以真实索引为准。

- 保留搜索框和一个可选跨 registry 搜索开关，不常驻命名空间/用法筛选标签。
- 包 ID 为主文本；版本为次文本；用法与项目状态一行，描述最多两行。示例/生态等次要标签移到详情，避免每行出现多枚同等权重徽标。
- 已声明状态用文字加主题色；当前选中包增加可见标记与 `aria-current`。不在整行按钮内部嵌套“添加”按钮。
- 支持 Tab/Enter 的基础操作；可进一步加入上下键移动结果、Enter 打开、Esc 清空搜索。键盘行为须与搜索框编辑行为明确区分。
- 查询仍在客户端即时过滤；保留当前多词匹配，并让精确 ID、名称前缀优先，其后为描述命中；无查询时稳定按 ID 排序。
- 保存 query、scroll、selectedKey；数据刷新后保留焦点和光标位置。使用 `setState/getState` 恢复被销毁的 webview，不依赖 DOM 长期存活。

### 4.2 搜索状态与来源

- 本地搜索始终立即可用；其它 registry 默认关闭。
- 启用后只对至少两个字符的查询发起搜索；清空/短查询及时清理旧附加结果。
- 每次请求记录 query、请求代次、开关及项目/源上下文；响应只提交到仍匹配的视图。关闭开关立即废弃在途结果。
- 显示“正在搜索其它 registry…”，不阻塞本地结果。其它来源单独分组，行内注明来源；状态分别显示本地命中数与额外结果数。
- 首期为非本地结果提供**有限预览详情**：包 ID、搜索返回的版本/描述、来源、可复制的检索命令，以及“如何获取完整详情”的说明。缺失字段不补造；暂不提供一键添加，避免把工具索引结果直接当作 C++ 库添加。
- 取消当前“能点击但详情必然在本地查不到”的流程；后续有稳定解析接口时再接入跨源完整详情，不以解析人类输出构造完整包模型。

### 4.3 空状态

| 状态 | 展示与恢复入口 |
| --- | --- |
| 初次读取 | “正在读取 mcpp-index…”；有旧快照时保留列表 |
| 官方索引缺失 | 说明缺失来源；提供更新索引、设置路径 |
| 显式路径无效 | 展示路径和原因；提供修改路径、重试 |
| 搜索无命中 | 展示当前查询；提供清空，以及可选搜索其它 registry |
| 读取/更新失败 | 简短原因、重试、查看输出；保留可用旧结果 |
| 无 mcpp 项目 | 可浏览；顶部提示尚未选择项目，详情主操作解释为何不可添加 |

## 5. 详情页布局

### 5.1 推荐信息顺序

1. **身份与概览**：包 ID、描述、用法、标准与许可；来源为次级信息。
2. **项目与添加控制**：目标项目、当前环境平台、版本选择、依赖类型，以及原有同行的添加/仓库/索引站操作。
3. **如何使用**：引入代码、真实示例及来源；用户无需越过全部平台版本矩阵。
4. **版本与平台**：当前平台完整列表，其他平台默认折叠查看。
5. **依赖与构建信息**：依赖清单、项目锁定对照、targets/include dirs；空白构建信息不单独占一节。
6. **来源与诊断**：本地路径、解析来源、索引版本、降级信息。

### 5.2 布局草图

```text
compat.argparse
Command line argument parser…
#include  ·  C++23  ·  MIT

目标项目  app-a     当前环境 linux
版本 [3.2 ▾]       依赖类型 [普通 ▾]
项目声明 3.1  ·  锁定解析 3.1
[切换到 3.2]        [仓库] [索引站]
mcpp add compat.argparse@3.2                   [复制]

如何使用                         包信息 / 平台版本
引入代码               [复制]     当前平台 linux
真实示例               [复制]     其它平台（折叠）
                                 依赖（数量）
                                 构建信息（折叠）
```

- 详情容器建议最大宽度约 1120px；可用宽度 ≥900px 时下半部分为主内容约 2/3、补充信息约 1/3。较窄编辑器降为单栏，不依赖窗口总宽度。
- 添加区保持首屏可见，不在页面底部重复按钮；宽窗口下主操作与外链仍同行，窄窗口自然换行。
- 暂不引入整页 tabs：当前信息量适合一个文档配局部折叠，避免用法和状态被藏在不同页签。
- 长包名允许换行，代码区单独横向滚动；布局不产生整页横向滚动。字体、颜色、焦点和分隔线沿用 VS Code theme tokens。
- 初次打开立刻显示包身份和局部加载状态；先展示本地轻量信息，解析完成只更新对应区块。切包时立即换标题和加载占位，不能让旧包按钮继续可操作。
- 保留单详情面板；重新点同一包保留版本、依赖类型、折叠项和滚动位置。切包可缓存少量会话状态，索引更新后校验所选版本是否仍存在。

## 6. 版本、项目与添加行为

### 6.1 版本选择

- 主操作区使用单一版本选择器，默认现有声明版本（仍在当前环境可用集合时），否则选择当前环境最新可用版本；显式展示存在更新，不自动升级。
- “最新”限定为当前环境，不表示跨平台最新。来自文本回退的可用性标记为“待 CLI 确认”；解析失败不能渲染成“确定无版本”。
- 主选择器只列当前环境可用版本。其他平台矩阵只读；查看其它平台不改变命令、不启用添加。
- 没有当前环境版本时禁用添加，明确原因；未知平台、解析失败、明确不支持平台分别处理。
- 当前环境平台依据现有 host 检测；工程目标识别属于后续 CLI 契约扩展，首期不以平台下拉框模拟切换编译目标。

### 6.2 项目依赖状态

统一列表和详情使用的项目状态模型，分别保留：`declaredVersion`、`resolvedVersion`、`dependencyKind`、`sourceType`。短名匹配必须在无歧义时采用；不同命名空间同名不能误判。

| 状态 | 主操作和显示 |
| --- | --- |
| 无项目 | 禁用添加；提供选择/打开项目入口 |
| 多项目 | 展示已选择项目；首次不能明确定位时要求选择一次 |
| 不受信任 | 可读本地内容；禁用运行 CLI 的操作并显示原因 |
| 未声明 | “添加到项目” |
| 同版本同分组已声明 | “已声明”，禁用重复操作 |
| 不同版本已声明 | “切换到 X”，同时展示现有声明和锁定值 |
| 同版本不同分组 | 不误判为已完成；仅在 CLI 确认支持安全迁移时提供“改为开发/普通依赖” |
| path/git 依赖 | 明确显示来源；首期不直接以 registry 版本覆盖，保留查看 manifest 入口 |
| 仅 lock 中存在 | 标记“锁定中”，不能当作项目直接声明或已安装 |

详情页绑定明确项目上下文；切项目后重新生成项目状态。提交时冻结 `{packageKey, projectRoot, version, dependencyKind, requestId, pageGeneration}`，操作期间即使焦点改变也不能重新选择写入项目。

首期继续通过 `mcpp add` 修改依赖。实现前验证其分组迁移、依赖替换、锁文件更新语义；未支持的操作应说明限制，不由扩展自行编辑 TOML 来补齐。

### 6.3 操作反馈与并发

- 点击添加立即进入 pending，按钮显示“正在添加…”，锁定本页版本/分组选择；host 同样去重。
- 包/项目/页面代次与响应匹配时才更新当前页面；A 的操作完成时，B 页面不接收 A 的已添加标记。A 的完成状态可写入对应项目状态并保存在操作记录中。
- 成功后重读 manifest/lock，以真实文件更新列表、详情和按钮；不只把请求中的版本当作最终状态。
- 复制使用按钮旁短暂“已复制”；外链失败在该操作附近提供复制链接/重试。它们不覆盖添加结果。
- 添加成功默认使用页内反馈；切走详情后使用通知。失败页内显示短原因与“查看输出/重试”，避免整段 stderr 同时填满通知和页面。
- 首期不新增伪取消按钮。若底层进程没有可靠取消接口，不能只隐藏 pending 却让命令继续运行。

## 7. 用法、示例和依赖信息的真实性

- 将真实示例、描述符明确声明的引入方式、推导的参考写法分别标注来源。
- 没有可验证的模块名/头文件路径时显示说明，不能把 `#include <foo.h>` 或按包名猜出的 import 当作可直接复制的真实用法。
- 本机打包索引目前没有 `tests/examples`，因此“暂无本地示例”是正常状态，不暗示包不支持使用。可提供已有的索引站链接；不自动联网补齐。
- 示例提供代码复制与来源文件信息；只在本地确有文件时提供打开文件操作。完整文件查看按需加载，不一次读完所有示例。
- 依赖信息要区分包描述符声明与当前项目 lock 对照；未确认所属版本时标为描述符层级信息，不能随着版本选择器变化就声称已切换到该版本依赖。
- 可解析为本地包的依赖支持打开详情；无法解析的显示文本和来源说明。首期不绘制完整依赖图。

## 8. 实施拆分

| 阶段 | 交付内容 | 主要文件 |
| --- | --- | --- |
| P0：数据与状态正确 | 新旧官方索引定位；默认排除 xim；源身份；依赖状态缓存拆分；操作绑定包与项目 | `indexLocator.ts`、`indexModel.ts`、`detailPanel.ts`、`addDependency.ts`、`extension.ts` |

不要求新增公共配置来控制每个布局细节。优先让默认行为正确，减少新增持久化设置。

## 9. 验收清单

### 9.1 必须覆盖的行为验证

1. 新版官方路径 + xim 并存：默认只显示官方源；以测试夹具计数断言，真实机器 252/337 只作本次证据。
2. 只有旧版官方路径、只有 xim、显式无效路径、显式 checkout、多 home/重复源分别有明确结果。
3. manifest/lock 保存、CLI 磁盘写入和项目切换后，列表与详情状态一致；未改变索引不重读全量描述符。
4. 查询 A 慢、查询 B 快以及关闭网络开关：A 结果均不能覆盖 B/重新出现。
5. 跨源结果可打开有限详情，不出现伪装成索引删除的错误页。
6. A 包添加期间切到 B/切换项目/关闭再打开页面：A 的结果不得修改 B 或写入新项目。
7. 当前平台无版本、其它平台独有版本、同版本跨平台、已有 dev、仅 lock、path/git、同名不同命名空间均正确展示。
8. 添加失败、解析超时、更新失败均可恢复，已有数据保留；取消/关闭加载不能留下旧操作控件。

对索引发现、缓存失效、操作关联和竞态补充行为测试；HTML 测试验证语义与可达性，不以大量脆弱的 DOM 字符串断言替代真实交互。

### 9.2 人工视觉与交互验收

- VS Code 真实窗口：侧边栏约 180/280/420px；详情约 480/800/1200px；浅色、深色、高对比主题。
- 首屏可判断目标项目、当前环境、所选版本和主操作；查看用法不必先滚过其它平台全部版本。
- 键盘可完成搜索 → 打开 → 选版本 → 添加；焦点可见，状态有文本，折叠和选择状态有 aria 表达。
- 搜索不重建文档、不丢光标；更新/重新打开不丢查询和滚动；添加/复制不引发整页刷新。
- 用网络延迟/解析超时模拟加载过程，确认不展示可操作的上一包内容。

性能目标为本地数百包查询输入流畅（单次过滤目标 <50ms），列表不为每个包启动 CLI；优先测量现状，只有实际规模要求时再引入虚拟列表。

## 10. 本次 review 建议确认的决策

1. **来源范围**：默认只浏览官方 mcpp-index；自定义路径明确标识，其它 registry 通过可选搜索进入。
2. **侧边栏密度**：保留搜索 + 一个跨源开关；行内只保留关键用法与项目状态，不恢复多行 chips。
3. **详情层级**：项目/版本/添加放首屏，用法和示例优先，平台矩阵与构建信息降为补充；宽屏双栏、窄屏单栏。
4. **版本行为**：默认保留现有可用声明版本；其它平台只读，当前环境版本由一个选择器控制。
5. **跨源边界**：首期做有限预览，未有完整数据的结果不提供一键添加。
6. **实施顺序**：先 P0 数据与并发正确性，再 P1 核心交互，最后 P2 视觉与键盘细节。


## 11. 实施期间的 review 调整（优先于前文布局草图）

- 移除叠加的顶部 margin/padding 和空反馈占位；没有本地示例或依赖时，不为每个空字段单独占用一节。
- `#include`/`import`、`C++23`、许可证作为使用主题颜色的小 tag，直接放在包名后；项目切换与当前环境位于右上角。
- 移除 dev checkbox。主添加按钮旁提供依赖类型二级菜单，包含项目依赖（`dependencies`）、开发依赖（`dev-dependencies`）、构建依赖（`build-dependencies`）。版本仍由唯一的当前环境选择器决定。
- 选普通/开发依赖时，按钮和 CLI 预览同步变化；选择构建依赖时，显示真实命名空间对应的 TOML 片段，主按钮变为“打开 mcpp.toml”。本机 `mcpp add --help` 仅提供 `--dev`，因此构建依赖不伪造 `--build`，也不自动写文件。
- 已在普通/开发分组声明的包切换到另一个分组时，同样提供清单编辑流程，不通过 CLI 制造重复声明或假定能安全迁移。
- 平台矩阵、构建信息和来源诊断默认收起。保持文档布局，不引入整页 tabs。
- 对选中项目同时提供文件事件监听和两个文件的低频 stat 检查；本地真实测试发现宿主 inotify 配额耗尽时，普通 watcher 会漏掉外部修改，stat 检查保证状态仍能更新。
